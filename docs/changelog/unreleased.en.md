## [Unreleased]

### Added

- **Monitoring output on Windows**: in **Preferences > Playback**, you can copy the audio output to headphones or speakers on another device. The arrow keys adjust the headphone level while the output feeding RadioBOSS stays at the **Broadcast volume** setting.
- **M4A downloads**: **Audio quality**, in Preferences and in the download dialog, has a new **M4A (AAC)** option. On YouTube, KeyTune takes the audio that already comes in M4A, without conversion and without needing FFmpeg, at a quality slightly below Original. From a site without M4A, the audio is converted with FFmpeg; without FFmpeg, it comes in the site's format, and the end-of-download notice says which.
- **User manual in a program window**: **Help > Open user manual** (and the button on the welcome screen) no longer opens the browser. The window shows the contents on the left and the text on the right, like Windows help. In **Contents**, the up and down arrows move through the sections, the right arrow opens a section and shows its topics, and the left arrow closes it. The text of the chosen item appears in **Text**, and `Enter` moves the focus there; `Esc` closes the window. Each field has a shortcut: `Alt+S` goes to the search, `Alt+O` to the contents and `Alt+X` to the text. The manual's links work: `Enter` on a line of the text that has a link follows the link. A part of the manual opens in the window itself, with the focus on the text; a website opens in the browser. The **Open in browser** button opens the full manual in the browser. The window does not block the player: you can keep listening and using the shortcuts while it is open, and `Alt+F6` switches between the manual and the main window. Opening the manual again brings back the window that is already open. In the search, type one or more words and press `Enter`: the contents show only the topics that have all of them (ignoring case and accents), with their sections already open, the program says how many it found and the text opens on the line with the word. `Enter` with the field empty brings the whole manual back. Each topic is short, and the shortcut tables become "key: what it does" lines. It follows the program language.
- **Spoken notices split by kind**: in **Preferences > Accessibility**, the **Notices that speak** list now has eight new kinds, besides the five event kinds that already existed: playback; track change and SponsorBlock; speed and pitch; modes turned on or off; navigation; progress; confirmations; and errors and unavailable actions. You can silence the track change and keep the time, volume and status you ask for with `T`, `V` and `S`, for example. Those three keys do not depend on the list. All of them come on, and the **Enable accessibility announcements** switch still applies on top. The option to speak while KeyTune is active still covers only the notices that arrive by themselves (chat, notifications, download and sleep timer).
- **Open KeyTube on startup**: in **Preferences > General > Startup and session**, **Open KeyTube on startup** opens the KeyTube tab together with the app. It is off by default and available only with the YouTube integration turned on in **Additional resources**.
- **Add to the playlist from Explorer**. File Explorer offers **Add to KeyTune playlist** for associated audio and video formats, even when another player is the default. The selected files go to the end of the playlist without interrupting playback. The option is registered during installation or in **Preferences > General**.
- **Portable version**. Extract `KeyTune-Portable.zip` and open `KeyTune.exe`. Each portable folder opens in its own instance, with file associations separate from the installed version. Data stays in `data`. If the folder is read-only, KeyTune warns that it will write to this computer. The updater checks the ZIP before closing the player and shows where it kept the backup if a file cannot be restored.
- **YouTube links clicked in other programs open in KeyTune** (Windows). A YouTube or YouTube Music video or playlist link clicked in WhatsApp, email or another program plays straight in the player. It is a workaround: Windows does not let a program take only the links of one site, so KeyTune registers as a browser, keeps the YouTube links and sends every other link, as usual, to the browser you used or to the one you choose in **Browser for other links**. To turn it on, use **Make KeyTune the default browser...** in **Preferences > General > YouTube links**, or check **Offer KeyTune as a browser** in the installer, and choose KeyTune for HTTP and HTTPS in Windows Default apps. To undo it, choose another default browser in Windows.

### Changed

- **`Alt`+letter shortcuts on dialog fields**: the fields on every Preferences tab and in the download, conversion, change history, update, playback queue, audio output, equalizer preset, plugin, YouTube connection and quick shortcuts help dialogs now have an underlined letter in their label. `Alt` plus that letter moves the focus straight to the field. Letters that were repeated within the same dialog changed, so each shortcut leads to one place only. In the download dialog, the **Download** list is now called **What to download**.
- **Opened files play without going into the playlist**: `Enter` on a file in the folder explorer, and a file opened from Windows File Explorer with KeyTune open, added the file to the current playlist. Going back to an earlier file kept playing all the ones you had heard after it. Both now play in the **Outside the playlist** tab, replaced on each file opened, and playback stops when the file ends. The playlist stays as it was, and focus stays where it was. To build a playlist, use `Shift+Enter` in the explorer or **Add to KeyTune playlist** in Windows. If you prefer the old way, uncheck **Play opened files without adding them to the playlist** in **Preferences > Playback**.

### Fixed

- **Alert sounds with KeyTune in the background**: when a new YouTube notification arrived with the window minimized, in the tray or unfocused, Windows played its own system sound instead of KeyTune's alert sound. The sound configured in KeyTune now plays the same way inside or outside the window, and trying to change tracks while KeyTube is still loading also uses KeyTune's failure sound instead of the Windows beep.
- **First item of a new page not announced in the KeyTube hub**: scrolling with Down Arrow to the end of a search or radio list and loading the next page left the first item of that page unannounced by the screen reader (only the item after it spoke again). Focus now moves straight to the first newly loaded item.
- **Next/previous track blocked by mistake**: changing tracks in a favorite online radio station, or in any playlist that isn't YouTube Music, was blocked while the YouTube Music hub was processing some operation (such as updating its additional resources or loading the library). That block now only applies to tracks that are actually YouTube Music.
- **Related content not announcing the track name**: advancing into related content (similar tracks) at the end of a YouTube Music playlist only announced "Related content", without the track name or its position in the list.
- **Shorts that sometimes failed to open**: opening Shorts in KeyTube now and then showed "YouTube returned no shorts right now", because the first short was looked up on the account's home feed, which doesn't always have the Shorts shelf. Shorts now open like the site's Shorts tab: YouTube itself picks the first one for the account and sends the sequence.
- **Track names in saved playlists**: saving a playlist with YouTube videos and songs lost their names, and opening it again showed the tracks as `watch?v=...`. The playlist now stores each track's name and shows the same names when you reopen it. Playlists saved before still open, but only get their names once saved again.
- **yt-dlp downloaded for no reason**: the automatic check of the additional resources downloaded yt-dlp every time, even without a new version. KeyTune now compares the installed version with the latest one and only downloads when they differ.
- **Freeze when preparing large playlists with AutoDJ**: with a playlist of hundreds of songs, AutoDJ analysis could leave the whole computer unresponsive for minutes, screen reader included. Analysis now uses far less memory and CPU, handles one track at a time and prepares only the next ones, so the player and the screen reader keep responding.
- **Message when starting an AutoDJ session**: **Play playlist with AutoDJ** was disabled or only said it was unavailable. The command now always stays in the **Playback** menu and says what is keeping the session from starting: AutoDJ turned off, the additional resources not installed yet (and where to install them), or the playlist empty or still loading.
